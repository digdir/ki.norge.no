# Decision log

Decisions and milestones, newest first. Each entry says what was decided, why, and where the details are. The log starts 2026-10-05. See [README](README.md) for what the folder is for.

## 2026-10-07

- **The CMS pod is pinned to the digest of the image tag.** "Publish Syncroot artifacts" looks up the digest the tag points to, and the pod is pulled by digest with the tag as a label. A tag that moves does not change what runs, and a tag that does not exist stops the publish before anything is pushed. `deploy-cms.sh` and `backup-prod.sh` read the reference in the form `umbraco:<tag>@sha256:…`. See [#861](https://github.com/digdir/ki.norge.no/pull/861) and [#844](https://github.com/digdir/ki.norge.no/issues/844).
- **The CMS pod has probes.** Without probes Kubernetes did not detect a pod that hung or had started without a database. Startup and liveness go to `/api/health`, which does not check the database, so a short database outage does not cause a restart. Readiness goes to `/api/health/ready`. Linkerd did not let the probes through because the `Server` has its own routes, so the probe paths got their own route. See [#863](https://github.com/digdir/ki.norge.no/pull/863) and [#876](https://github.com/digdir/ki.norge.no/issues/876).

## 2026-10-06

- **Skyra does not get `'unsafe-eval'` in the CSP.** The survey works with the current policy. The violation shown in the console comes from a check in Zod 4 (`allowsEval`) that tries `eval` inside a try/catch and tolerates being blocked. Allowing `eval` would weaken the policy for the whole site without anything working better. See [#841](https://github.com/digdir/ki.norge.no/issues/841) and [#856](https://github.com/digdir/ki.norge.no/pull/856).
- **Enforcing that the CMS pod does not run as root waits a few days.** [#859](https://github.com/digdir/ki.norge.no/pull/859) sets `runAsNonRoot` and `runAsUser: 1654` at pod level. Images built before [#858](https://github.com/digdir/ki.norge.no/pull/858) run as root and do not start with it, so a rollback to the previous image would have stopped the CMS. The PR is merged when both environments have run an image from #858 for a while. Part of [#843](https://github.com/digdir/ki.norge.no/issues/843).
- **The Delivery API is not closed until there is a separate read key.** Today the single API key opens both published content and drafts. Requiring a key for reading means handing it out to everyone who reads the API, among them the search crawler and the smoke test in CI. The CMS reads the key only at startup, so a rotation without overlap can take down the site. The first step, that the frontend always sends a key, can be done independently. The finding is rated low, because drafts already require a key. See [#842](https://github.com/digdir/ki.norge.no/issues/842).
- **The security round of 6.10 is in prod.** [#850](https://github.com/digdir/ki.norge.no/pull/850)–[#858](https://github.com/digdir/ki.norge.no/pull/858) were merged, tested in tt02 and rolled out 6.10. The CMS image and the frontend are built from `78b1ce9`. The changes fixed the findings from the review of 5.10:
  - CSP without `'unsafe-inline'` in `script-src`. Astro hashes the scripts instead of using a nonce, because the responses are cached at the edge and a hash is the same for all visitors. The policy is in `apps/frontend/src/lib/csp.ts` ([#856](https://github.com/digdir/ki.norge.no/pull/856), [#841](https://github.com/digdir/ki.norge.no/issues/841)).
  - Turnstile rejects submissions when the secret is missing, and checks the hostname. tt02 has its own rate limit counters, so they are not shared with prod ([#853](https://github.com/digdir/ki.norge.no/pull/853)).
  - `/admin-tilgang` has an expiry the server checks, a limit on the number of attempts and a form, so the key does not have to be in the URL ([#857](https://github.com/digdir/ki.norge.no/pull/857)).
  - The CMS shows diagnostics only in Development, readiness responds without the exception message, HTML responses have frame protection, and the Entra setup requires https ([#854](https://github.com/digdir/ki.norge.no/pull/854)).
  - The CMS container runs as UID 1654 instead of root, with `fsGroup` on the volumes ([#858](https://github.com/digdir/ki.norge.no/pull/858), [#843](https://github.com/digdir/ki.norge.no/issues/843)).
  - "Docker build and publish" rejects an image tag that already exists ([#851](https://github.com/digdir/ki.norge.no/pull/851), [#844](https://github.com/digdir/ki.norge.no/issues/844)).
  - CI runs a type check of the frontend ([#852](https://github.com/digdir/ki.norge.no/pull/852)). Astro's dev toolbar is turned off ([#850](https://github.com/digdir/ki.norge.no/pull/850)), and `frontend:dev:mock` works under Astro 7 ([#855](https://github.com/digdir/ki.norge.no/pull/855)).
- **The filters on /ki-tiltak went to tt02 before prod.** [#849](https://github.com/digdir/ki.norge.no/pull/849) adds filters on phase, delivery and type of AI, and free-text search in the metadata. The goal is that everything shown on the page can be searched, and that the categories can be filtered. The change affects what users see, so it was shown in tt02 first and went to prod with the frontend rollout the same day.
- **"NA" always becomes `null` or is removed, and a new export is prepared with one command.** `apps/frontend/scripts/klargjor-ki-tiltak.mjs` corrects the register's variants to our values and applies the overrides in `ki-tiltak-overstyringer.json`, each of which has a justification. The report shows what deviates. The next update therefore gives the same result every time. See [#848](https://github.com/digdir/ki.norge.no/pull/848) and [ki-tiltak-fields.md](../ki-tiltak-fields.md).
- **The name table is the default for organisation names, and the capitals are a fallback.** The register's export has the names in capitals. `ki-tiltak-virksomhetsnavn.json` gives each org number a display name, and the switch `VIRKSOMHETSNAVN` is set to `'tabell'`. If an org number is missing from the table, the name is shown in normal case and never in capitals. A test stops when an org number is missing. The list of 146 initiatives went to tt02 and prod 6.10. See [#847](https://github.com/digdir/ki.norge.no/pull/847), part of [#827](https://github.com/digdir/ki.norge.no/issues/827).
- **The new KI-tiltak list was taken out of main before the prod rollout of the security fixes.** The list from [#829](https://github.com/digdir/ki.norge.no/pull/829) was not approved for prod, and a prod deploy includes everything on main. [#840](https://github.com/digdir/ki.norge.no/pull/840) restored the list, and the frontend went to prod from `bd6854f` with the old list.
- **Trivy findings are fixed before the next rollout.** source-map-js was bumped to 1.2.2 for a HIGH vulnerability that only applies to building ([#846](https://github.com/digdir/ki.norge.no/pull/846)). Trivy has been green since, so a red alert is treated as a signal.
- **The unresolved findings from the security review became separate issues.** CSP with inline scripts ([#841](https://github.com/digdir/ki.norge.no/issues/841)), Delivery API without a key ([#842](https://github.com/digdir/ki.norge.no/issues/842)), CMS as root ([#843](https://github.com/digdir/ki.norge.no/issues/843)), image tags that can be overwritten ([#844](https://github.com/digdir/ki.norge.no/issues/844)) and minor findings ([#845](https://github.com/digdir/ki.norge.no/issues/845)). #841, #843, #844 and #845 are handled in the security round above. #843 waits for the enforcement in #859, and #842 waits for a separate read key.

  - The admin check also covers `/status/`, `/status.md` and percent-encoded paths ([#832](https://github.com/digdir/ki.norge.no/pull/832)).

  - The CMS proxy redirects http to https and sets HSTS ([#833](https://github.com/digdir/ki.norge.no/pull/833)), and SVG from media cannot run scripts on the CMS host ([#834](https://github.com/digdir/ki.norge.no/pull/834)).
  - The cache worker redirects http to https on ki.norge.no ([#835](https://github.com/digdir/ki.norge.no/pull/835)).
  - The syncroot workflow takes the image tag via `env` and validates it, instead of inserting it directly into the script ([#837](https://github.com/digdir/ki.norge.no/pull/837)).
  - An expired Delivery API key has been removed from the smoke test ([#838](https://github.com/digdir/ki.norge.no/pull/838)).
  - Dependencies: the js-yaml override has been removed ([#830](https://github.com/digdir/ki.norge.no/pull/830)), `@types/node` follows the runtime on v24 ([#831](https://github.com/digdir/ki.norge.no/pull/831)), and http-cache-semantics has been bumped to 4.3.0 ([#839](https://github.com/digdir/ki.norge.no/pull/839)).
- **New KI-tiltak list only to tt02, prod waits until the list is approved.** The register's export from 2026-10-05 ([#829](https://github.com/digdir/ki.norge.no/pull/829)) had new ids and values that deviate from the term list, and was shown in tt02 for review before prod.
- **Preview of drafts is gathered behind one validated entry point and is in prod.** Middleware decides preview in one place, and the secret from the CMS is checked. Without a valid secret, preview is off. The prod rollout waited until the secret was set for the prod worker. See [#723](https://github.com/digdir/ki.norge.no/pull/723).
- **Search falls back to BM25 when the semantic part fails.** The embedding model scales to 0 and cold-starts, and then search returned "Ingen resultater". A minimum of one instance is not saved on Elastic Serverless, so the fallback is the solution. See [#824](https://github.com/digdir/ki.norge.no/pull/824), [#822](https://github.com/digdir/ki.norge.no/issues/822) and [elasticsearch-index.md](../elasticsearch-index.md) ([#828](https://github.com/digdir/ki.norge.no/pull/828)).
- **Renovate creates all the PRs in the Thursday window the same morning** (`prHourlyLimit: 0`). See [#828](https://github.com/digdir/ki.norge.no/pull/828) and [dependencies.md](../dependencies.md).

## 2026-06-04

Written after the fact 2026-10-13. Source: [#351](https://github.com/digdir/ki.norge.no/pull/351), and the survey in `docs/seeder-content-write-audit.md`, which is in the git history.

- **Content is never written from startup code.** `ContentSeeder` created and published content nodes at startup and ran one-off structure migrations. The only guard was `LAUNCH_MODE`, which was not set in dis-core, so the seeder ran in prod and tt02 and published a duplicated guidance guide. It was the third time content writing from startup caused an incident in prod. The seeder was deleted, and content is created in the backoffice.
